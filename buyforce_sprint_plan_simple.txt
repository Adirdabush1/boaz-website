BuyForce MVP – חלוקה ל-6 בעלי תפקידים (ספרינטים דו-שבועיים)
המטרה: שכל אחד ידע בדיוק מה לעשות גם אם זו הפעם הראשונה שלו.
מבנה: לכל ספרינט יש רשימת משימות קטנה לכל אדם, מסודרת בצעדים פשוטים.

אנשים (נשארים קבועים בכל הספרינטים):
1. רפאל – מוצר ואסטרטגיה (מקבל החלטות, כותב יעדים)
2. דנה – עיצוב UX/UI ותוכן (Figma, קופי, שפה חזותית)
3. נועם – פרונט Web ב-Next.js
4. שירה – מובייל ב-React Native
5. איתמר – בקאנד, APIs, מסדי נתונים ותשלומים (Nest.js + PostgreSQL + Redis)
6. אלון – DevOps, CI/CD, בדיקות, ניטור ואבטחה

Sprint 0 (01-14.12.2025) – הקמה וסנכרון
• רפאל:
  - לפתוח את מסמך ה-PRD, לעבור סעיף-סעיף ולסמן "אושר" או "נדרש ברור".
  - להגדיר 5 KPI בסיסיים (לדוגמה: מספר משתמשים, אחוז השלמת קבוצה) ולכתוב אותם בלוח Monday.
  - ליצור ב-Monday לוח "BuyForce MVP" עם עמודות: ספרינט, בעל תפקיד, סטטוס.
• דנה:
  - לבחור פלטת צבעים בסיסית (ראשי, משני, רקע) ולהוסיף אותה ל-Figma.
  - לבחור שני פונטים (כותרות וטקסט רגיל) ולרשום למה בחרת בהם.
  - ליצור 3 כפתורים בפיגמה (ראשי, משני, לינק) ולהוסיף הערות שימוש.
• נועם:
  - לפתוח פרויקט Next.js חדש עם `npx create-next-app` ולדחוף לריפו הראשי.
  - לוודא שהפרויקט החדש יושב בתוך המונורפו ולהריץ `npm run dev` לבדיקה.
  - ליצור קומפוננטה פשוטה לניווט עליון (לוגו + מקום ל-Icons) ולהעלות PR.
• שירה:
  - להריץ `npx react-native init buyforceApp`, להוסיף ספריות React Navigation + SafeArea.
  - לפתוח את האפליקציה גם על iOS Simulator וגם על Android Emulator ולצלם מסך כהוכחה שעובד.
  - ליצור מסך פתיחה עם טקסט "BuyForce" לוודא שה-Navigation עובד.
• איתמר:
  - לשרטט דיאגרמת קופסאות פשוטה (Frontend, Backend, DB, Tranzilla) בלוסידצ׳ארט או דוקס.
  - לפתוח פרויקט Nest.js, ליצור מודולים ריקים: Auth, Users, Catalog, Groups, Payments.
  - לרכז בקובץ אחד את כל המפתחות (Tranzilla/Firebase/SendGrid) ולהכניס ל-Vault/Secrets Manager.
• אלון:
  - להגדיר מונורפו (NX או Turborepo) ולוודא שכל הפרויקטים (Web/Mobile/Backend) נבנים ממנו.
  - להקים GitHub Actions שמריץ `npm install` + `npm test` לכל חבילה.
  - ליצור קבצי env נפרדים ל-local/staging/prod ולהגדיר איפה שומרים אותם (לא בגיט).

Sprint 1 (15-28.12.2025) – זהות משתמש ו-Shell אפליקטיבי
• רפאל:
  - לקרוא את מסכי ההרשמה/התחברות שהמעצבת מכינה ולכתוב הערות בשפה פשוטה.
  - לבדוק את חוויית ה-Onboarding ולוודא שהמסרים מסבירים את מודל ה-1₪.
  - לעדכן בלוח ה-KPI האם היעדים של Sprint 0 הושלמו.
• דנה:
  - ליצור בפיגמה 3 שקופיות Onboarding (כותרת, טקסט קצר, איור או אייקון).
  - לעצב Header עליון (לוגו, כפתור חיפוש) ו-Bottom Nav עם 5 אייקונים.
  - לעצב מסך פרופיל פשוט: תמונת פרופיל, שם, אימייל, כפתור "עריכה".
• נועם:
  - לבנות טופס הרשמה (אימייל, סיסמה, כפתור) וטופס התחברות ב-Next.js, כולל הודעות שגיאה פשוטות.
  - לחבר את ה-Header וה-Bottom Nav כך שיהיו זמינים בכל הדפים.
  - להציג בפרופיל את הנתונים שמגיעים מה-API (שם, אימייל) או Placeholder אם אין.
• שירה:
  - להוסיף במסך הפתיחה Onboarding עם שלושה דפים שאפשר לדפדף ביניהם.
  - ליצור מסכי Login/Register עם ולידציה בסיסית (שדה ריק -> הודעה בעברית).
  - להוסיף Bottom Tabs עם האייקונים שהמעצבת נתנה ולהראות את מסך הפרופיל עם נתונים דמיוניים.
• איתמר:
  - להגדיר ב-Nest את Firebase/JWT Guard ולהוסיף הגנה לכל ה-EndPoints הפרטיים.
  - לבנות מסלולים: POST /auth/register, POST /auth/login, GET/PATCH /user/me, GET/PATCH /user/settings.
  - לבנות זרימת "שכחתי סיסמה": API שמקבל אימייל, שולח קישור דרך Firebase/SendGrid, ולרשום מסמך הסבר.
• אלון:
  - לכתוב בדיקת Cypress למשתמש שממלא טופס הרשמה ומקבל הודעת הצלחה.
  - להוסיף בדיקת Detox דומה לאפליקציה (אפשר עם נתונים דמיוניים אם ה-API עוד לא קיים).
  - להגדיר שליחה אוטומטית של אירועי Mixpanel/GA4: onboarding_view, registration_success, login_success.

Sprint 2 (29.12.2025-11.01.2026) – קטלוג, דף בית וחיפוש
• רפאל:
  - להכין רשימה של 8 קטגוריות (למשל: אלקטרוניקה, ריהוט) ולהוסיף לכל קטגוריה תיאור קצר.
  - לאשר את הטקסטים שיופיעו בדף הבית (כותרות המקטעים).
  - לאסוף מידע על 3 מוצרים לדוגמה (שם, מחיר רגיל, מחיר קבוצתי) ולהעביר לכולם בקובץ Google Sheet.
• דנה:
  - לעצב גריד קטגוריות עם אייקון וטקסט קצר מתחת.
  - ליצור כרטיס מוצר עם תמונה, שם, מחיר רגיל, מחיר קבוצה, באדג' הנחה ולב.
  - לעצב מסך Wishlist (מצב מלא + מסך ריק) וחיפוש במסך מלא כולל מקום להצעות.
• נועם:
  - לקרוא את הנתונים מ-/categories ולהציגם בגריד אינסופי (Responsive).
  - ליישם את דף הבית: שלושה מקטעים (Near Goal, Deals, New) עם Skeleton בזמן טעינה.
  - לבנות דף מוצר עם קרוסלת תמונות, תיאור ומד התקדמות.
  - להוסיף כפתור ♥ שמוסיף ל-Wishlist וקומפוננטת חיפוש שמושכת הצעות מה-API.
• שירה:
  - ליצור במסך הבית רכיבים דומים (קטגוריות, שלושה מקטעים) ב-React Native.
  - לבנות דף Wishlist בסיסי שמראה רשימת מוצרים שהגיעו מה-API.
  - ליצור Modal חיפוש במסך מלא עם רשימת הצעות + טקסט "אין תוצאות" כשהרשימה ריקה.
• איתמר:
  - לבנות טבלאות PostgreSQL: categories, products, product_images, wishlist.
  - ליצור את ה-APIs: GET /categories, GET /products (עם פרמטר קטגוריה), GET /product/:id, GET/POST/DELETE /wishlist, GET /search/suggestions.
  - להוסיף שכבת Redis שמחזירה תשובה מהירה לשלושת מקטעי הבית (TTL קצר).
• אלון:
  - להריץ בדיקות ביצועים (`k6` או `autocannon`) כדי לוודא שכל אחד מה-APIs עובר את 300ms.
  - להוסיף ניטור בסיסי (Grafana/CloudWatch) שמציג זמני תגובה לשירותים החדשים.
  - לבדוק שה-Deploy מריץ מיגרציות DB לפני שהשירות עולה.

Sprint 3 (12-25.01.2026) – קבוצות וזרימת "הצטרף בשקל"
• רפאל:
  - להגדיר מסמך קצר עם חוקים: כמה משתתפים צריך לקבוצה, מה קורה כשהקבוצה מלאה, מהי הודעת ברירת המחדל.
  - לכתוב טקסטים למסכי שגיאה (לדוגמה: "הקבוצה כבר מלאה", "נסו שוב את התשלום").
  - לאשר את טקסטי ה-Push לאבני הדרך (70%, 95%).
• דנה:
  - לעצב כרטיס קבוצה עם Progress Bar, טיימר, וכפתור "הצטרף בשקל".
  - ליצור מסך פרטי קבוצה שמראה: יעד משתתפים, רשימת אנשים (Placeholder), טיימר.
  - לעצב מודל אישור הצטרפות + מצבי שגיאה ברורים עם צביעות.
• נועם:
  - להוסיף כפתור "Join for 1₪" בדף מוצר ולקשר אותו למודל המעצבת.
  - לבנות דף "הקבוצות שלי" עם טאבים (Active, Closing Soon, Charged, Refunded, Failed).
  - לדאוג שמוצרים שהצטרפת אליהם יקבלו תג "Joined✔" בתוך הכרטיס.
• שירה:
  - לשכפל את אותו Flow במובייל: כפתור הצטרפות, מודל אישור, מסך "הקבוצות שלי" עם גלילה אנכית.
  - להוסיף טאבים במובייל עם הכותרות בעברית ולעדכן סטטוס כל 30 שניות (polling פשוט).
  - להציג הודעות הצלחה/שגיאה בסנאק-בר ברור.
• איתמר:
  - ליצור טבלאות groups ו-group_memberships עם כל השדות הדרושים (סטטוס, joined_count, deadline).
  - לבנות שירות ב-Nest שמעדכן סטטוסים (OPEN, LOCKED, FAILED) לפי חוקים.
  - לבנות APIs: POST /group/join (בשלב זה בלי תשלום אמיתי – רק PREAUTH מדומה), GET /group/:id, GET /user/groups, ולהוסיף Scheduler שבודק Deadlines כל כמה דקות.
• אלון:
  - לכתוב בדיקת אינטגרציה שמדמה משתמש שמצטרף, רואה את הסטטוס משתנה ואז הקבוצה נסגרת.
  - להגדיר התראות (Slack/Email) אם תור ה-Scheduler לא רץ או אם סטטוס תקוע יותר מ-10 דקות.
  - לתעד קובץ Runbook קצר: מה עושים אם הקבוצה לא משתנה סטטוס.

Sprint 4 (26.01-08.02.2026) – תשלומים ונוטיפיקציות
• רפאל:

  - להחליט מה מודדים אחרי הסשן (לדוגמה: כמה זמן לוקח משליחת הודעה ועד תגובת המשתמש).
• דנה:
  - לעצב תבניות Email (HTML פשוט) ל-4 מצבים: הצטרפות, 70%, הצלחה, כישלון.
  - ליצור מסך Notifications באפליקציה עם רשימת קלפים (כותרת, תיאור, זמן) + אייקון לפי סוג.
  - לעצב הודעת שגיאה תשלום שמופיעה בדף מוצר ובפרופיל.
• נועם:
  - להציג הודעת תשלום מתאימה (בהתאם לשדות שחוזרים מה-API) בדף מוצר ובפרופיל.
  - לפתח מסך Notifications ב-Web שמביא נתונים מ-/notifications ומאפשר סימון "נקרא".
  - להוסיף לוגיקה שמקפיצה Toast כשהתשלום נכשל ומציע "נסה שוב".
• שירה:
  - להציג את סטטוס התשלום בתוך מסך הקבוצה (לדוגמה: "החיוב הסופי עוד לא נעשה").
  - ליצור מסך Notifications במובייל עם אינדיקציה להודעות שלא נקראו.
  - להוסיף אפשרות לקפוץ למסך הרלוונטי בלחיצה על פוש (Deep Link בסיסי).
• איתמר:
  - לחבר ל-Tranzilla Sandbox: לכתוב שירות שמבצע PREAUTH 1₪, CHARGE מלא, REFUND מלא.
  - ליצור טבלת transactions עם שדה idempotency_key ולוודא שאין כפל חיובים.
  - לבנות NotificationModule שמאזין לאירועי GROUP_70,GROUP_95,GROUP_SUCCESS,GROUP_FAILED,PAYMENT_FAILED.
• אלון:
  - להגדיר תור BullMQ עבור תשלומים ונוטיפיקציות, כולל קונפיג בקובץ `.bullrc` (או קובץ env).
  - להוסיף לוגים מפורטים לכל שלב בתור (attempt, success, failure) ולהכניס ל-Grafana.
  - לבדוק תרחיש שבו ה-Push נכשל ולוודא שיש retry + התרעה.
